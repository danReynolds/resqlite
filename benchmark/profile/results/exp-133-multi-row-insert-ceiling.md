## Reading the table

- `rows_per_step=1` is the current executeBatch shape: one user row per `sqlite3_step`.
- `rows_per_step>1` generates a multi-row `INSERT ... VALUES (...), ...` statement and binds one chunk per native batch set.
- `chunk_build_us` is prototype overhead for building chunked Dart param sets. A production implementation could pack directly from original rows, so `wall_ms` is the useful ceiling and `effective_ms` is a conservative prototype cost.
