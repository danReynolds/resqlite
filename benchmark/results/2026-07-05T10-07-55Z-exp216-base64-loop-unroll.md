# Exp 216 - Base64 loop unroll for selectBytes BLOBs

Focused `benchmark/experiments/select_bytes_blob_base64.dart` A/B against
`origin/main` at `ea17249`. Candidate unrolls the native
`json_write_base64` payload loop in `native/resqlite.c` so each loop trip
encodes four 3-byte groups instead of one. JSON quote framing, base64 table,
padding, and output bytes are unchanged.

Harness reports median microseconds per `selectBytes()` query. Lower is
better.

## Delta summary

Candidate vs matching-pair baseline, negative = candidate faster.

| Lane | P1 (b -> c) | P2 (c -> b) | P3 (b -> c warmed) |
|---|---:|---:|---:|
| 10k rows x 8 tiny blobs (3B) | -5.8% | +1.5% | +0.6% |
| 10k rows x 20 tiny blobs (3B) | -4.7% | -0.4% | +3.8% |
| 10k rows x 8 small blobs (16B) | -5.9% | -6.9% | -34.4%* |
| 10k rows x 4 medium blobs (128B) | -1.1% | -9.3% | -4.7% |
| 1k rows x 2 large blobs (4KB) | -13.6% | -12.9% | -11.9% |
| 10k rows x 8 mixed (4 blob + 2 int + 2 text) | -2.1% | -3.7% | -5.1% |

*Small-BLOB P3 is contaminated by a slow baseline outlier.

The 4KB large-BLOB lane is the cleanest load-bearing signal: baseline is
stable at 4786-4918 us/query and candidate is stable at 4170-4332 us/query,
for a reproduced 11.9-13.6% win. Medium BLOBs stay candidate-faster in all
three passes, but the baseline varies enough that the magnitude is a broader
1.1-9.3% band. Tiny 3B lanes are guards: they do not consistently move
because each BLOB cell executes only one 3-byte triplet, leaving little loop
control work for a four-triplet unroll to remove.
